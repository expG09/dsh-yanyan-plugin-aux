# 砚砚工具包 · dsh-yanyan-plugin-aux

仓库：<https://github.com/expG09/dsh-yanyan-plugin-aux>

DeepSeek Harness 的辅助插件包，目前管三件事：

1. **上下文水位读数 + 三档提醒**：每个 turn 的第一步注入一条占用读数（已用 / 窗口 / 百分比）。
   占比跨过三档线时各额外注入一次提醒，同一会话每档只提醒一次：
   - `handoverPercent`（默认 50）：该写交接了，长任务先把结论落盘；
   - `compactSoonPercent`（默认 75）：快到折叠线了，折叠只留摘要、细节会丢；
   - `nearlyFullPercent`（默认 90）：快满了，该换新会话了。
2. **时钟续行**：按固定间隔往一个文本文件追加 `YYYY-MM-DD HH:mm` 一行；能读到占用时行尾带上百分比。
   进程启动时先补一行，把上次关机期间的空白收口。
3. **换新提醒**：按周期三选一（按间隔 / 每周 / 每月）注入「该换会话」提醒，提醒过就记状态；
   到点那一拍还会另外往时钟文件写一行 `YYYY-MM-DD HH:mm · 该换会话`（能读到占用时带 ` 上下文 NN%`）。
   **换新动作不在插件里**——只提示，实际换会话走外置脚本 `tools/rotate-qq-session.mjs`
   （先写交接、再改绑定、最后重启）。

前两件只做**读数和提示**，不改任何行为、不代替折叠、不删历史；第三件只发提醒，不读写任何别人的存储。

三件事的注入都受顶层 `scopeSessions` 限定：留空 = 所有会话；填了会话 id（或前缀）就只在那些会话里注入。
**时钟行不受它影响**，按 `clockIntervalHours` 照常写。

## 为什么做这个

长会话会一直折叠、一直累计。折叠只压当前窗口，压不掉累计消耗；判断「这一场该不该换新」需要一个模型
自己看得见的读数。界面上有那个百分比，但模型读不到它——这个插件把它注入进去。

另外两种提醒分开，是因为它们要求你做的事不一样：50% 只是「先落盘」，75% 是「要折叠了，细节会丢」，
90% 是「这场该收了」。一句话糊在一起，等于没有提醒。

## 安装

在 DSH 里 **插件 → 添加插件 → 选本地目录**，指到本仓库目录；或者用
`dsh plugin --profile <name> add file:<绝对路径>`。

装完重启桌面端（从托盘退出，不是关窗口）才生效。

## 装在哪里找

⚠️ **配置页不在插件页，也不在左侧主侧边栏。**

装好重启后：点**设置** → 左侧导航里找**「砚砚工具包」**（排在「语音模式」附近）。那一页才是改配置的地方。

插件页只显示它的介绍和图标，一个字都改不了——这是最容易让人以为"没装上"的地方。

## 配置

行 id 是 `aux`。`cordis.patch.yml` 里的十二项是**出厂默认**；装好之后在
**设置 → 砚砚工具包** 里改，保存即生效，不用重启：

| 键 | 默认 | 说明 |
|---|---|---|
| `scopeSessions` | `[]` | 全局生效范围。空数组 = 所有会话都收到读数与提醒；非空时只有会话 id 等于某一项、或以某一项开头的会话才会收到**任何注入**（读数、三档提醒、换新提醒）。**只管注入，不管时钟**——时钟行照常写。非数组回落默认。 |
| `clockFile` | `G:\yanyan-workspace\report-cache\clock.md` | 时钟文件绝对路径，父目录不存在会自动建。 |
| `clockIntervalHours` | `6` | 两次追加之间的间隔（小时），合法范围 1–168。 |
| `injectPerTurn` | `true` | 每轮第一步是否注入读数。关掉只影响读数，三档与换新提醒照常。 |
| `handoverPercent` | `50` | 提醒交接线（%），钳制到 1–100。 |
| `compactSoonPercent` | `75` | 即将折叠线（%），钳制到 1–100，必须大于 `handoverPercent`。 |
| `nearlyFullPercent` | `90` | 即将用完线（%），钳制到 1–100，必须大于 `compactSoonPercent`。 |
| `rotateReminderMode` | `'weekly'` | 换新提醒周期：`interval` / `weekly` / `monthly`。非法值回落 `weekly`。 |
| `rotateReminderDays` | `7` | 仅 `interval` 模式用：隔几天提醒，钳制到 1–365。 |
| `rotateReminderWeekday` | `6` | 仅 `weekly` 模式用：0 = 周日 … 6 = 周六；越界或非法回落 6。 |
| `rotateReminderDayOfMonth` | `1` | 仅 `monthly` 模式用：每月几号，1–28（每月都有）；越界回落 1。 |
| `timeZone` | `Asia/Shanghai` | 时钟行、以及换新提醒算「周几 / 几号」用的 IANA 时区。 |

三个百分比必须递增。设置页保存前会先拦一道：不递增就地报错、不发请求；后端 `normalizeSettings`
还会再修一道——越界的先钳制到 1–100，然后把三档按从小到大重排，仍然相等（比如三项都填 90）就
从低到高各加 1 撑开（`[90,90,90]` → `[90,91,92]`）。

设置页把值保存在 `%USERPROFILE%\.dsh\aux-settings.json`；「恢复默认」会删掉这个文件，回到 patch
里的值。也可以直接改那个 JSON —— 宿主每次 pre-step 与时钟 tick 前都会看文件 mtime，变了就重读。

## 换新提醒

- **状态文件**：`%USERPROFILE%\.dsh\aux-state.json`，只放状态、不放设置，形如
  `{ "lastRotateReminderAt": "2026-11-18T12:00:00.000Z" }`。文件不存在 / 读坏 = 从没提醒过。
- **什么时候提醒**：**每次 pre-step 都检查**（不限第几步）；从未提醒过（第一次运行）→ 立刻提醒；
  之后按 `rotateReminderMode` 判到期：
  - `interval`：距上次提醒满 `rotateReminderDays` 天（1–365）；
  - `weekly`：上次提醒之后最近的、落在 `rotateReminderWeekday`（0=周日 … 6=周六）的自然日到了；
  - `monthly`：上次提醒之后最近的、`rotateReminderDayOfMonth`（1–28）那个自然日到了。

  「周几 / 几号」都按 `timeZone` 算本地日期，不是 UTC。到点只注入一条：
  「本周换会话提醒：这一场已经用了 X%（窗口 Y）。要换就说一声，我按 `tools/rotate-qq-session.mjs`
  走——先写交接，再改绑定，最后重启。」
- **补提醒**：关机期间错过的那次，下次打开的第一轮就会补上，而且只补一次（写完时间就不到期了）。
- **时钟文件里留一行**：到点注入的同一次，另外往 `clockFile` 追加一行
  `YYYY-MM-DD HH:mm · 该换会话`，能读到水位时再带 ` 上下文 NN%`（例：
  `2026-11-18 20:50 · 该换会话 上下文 66%`）。它跟按 `clockIntervalHours` 写的常规时钟行是两回事，
  互不覆盖、也不去重；写失败吞掉，不影响注入。
- **生效范围（全局）**：`scopeSessions` 非空时，只有会话 id 等于某一项、或以某一项开头的会话
  才会收到**任何注入**（读数、三档提醒、换新提醒）；空数组 = 所有会话。范围外的会话一条都不注入，
  也不推进读数门限、已提醒档位和换新提醒状态。跳过时会在时钟文件同目录的 `aux-debug.log`
  里写一行 `skip scope session=<id>`，方便排查「这个会话怎么没读数」。**时钟行不受影响**。
- **换新本身不在这里**：插件不读不写 qqbot 的 `model-prefs.json`，也不缓存任何绑定。实际换会话
  由外置脚本 `tools/rotate-qq-session.mjs` 做（先写交接，再改绑定，最后重启桌面端）。
- 读不到状态文件、写失败都不影响会话：读失败当作从没提醒过，写失败吞掉（本进程内另有内存计时兜底，
  不会每个 pre-step 重复提醒）。

## 已知限制

- **读不到水位就不注入**：`pressureTokens` 或 `contextWindow` 缺失、为 0 时静默跳过，不会伪造读数。
  这通常意味着宿主刚启动、还没发出过请求。
- **提醒只按会话内存记**：插件重启后，同一会话的三档提醒会重新计一次。
- **生效范围只认会话 id 前缀**：`scopeSessions` 是字符串前缀匹配（等于或以其开头），写错前缀那个会话
  就一条注入都收不到；留空最稳（所有会话都收）。范围外的会话连读数都没有，这是刻意的。
- **时钟行只随进程活着写**：电脑关机或桌面端退出期间不会写；下次启动补一行，但中间那段的空白不会补。
- **换新标记行只在到点那一次写**：`· 该换会话` 那一行是提醒时的附加记录，常规时钟行不会带它；
  两者碰巧同一分钟都写也并排留着。
- **只注入文本**：不提供模型可调用的查询工具，读数只在每轮开头可见。
- **没有 webServer 的 profile 不挂接口**：`webServer` 服务不是必需项，探测不到就只跳过 `/api/aux`
  路由（设置页不可用），水位、提醒与时钟照常跑。
- 不接管 DSH 的自动折叠，也不改变压缩阈值——那是 `compaction-basic` 的事。

## 开发

改 `index.js` 后，ESM 语法检查用自带的解析器（`node --check` 对含 `export` 的文件会直接放行，别信它）：

```sh
node --experimental-vm-modules <check-esm-syntax.mjs 的路径> index.js
```

`client.js` 是自注册脚本而不是 ESM，用另一支检查：

```sh
node <check-client-script.cjs 的路径> client.js
```

纯逻辑都有普通 node 测试（不装依赖）：

```sh
node test/settings.test.mjs
node test/rotate-schedule.test.mjs
```
