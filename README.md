# 砚砚工具包 · dsh-yanyan-plugin-aux

仓库：<https://github.com/expG09/dsh-yanyan-plugin-aux>

DeepSeek Harness 的辅助插件包，目前管三件事：

1. **上下文水位读数 + 四档提醒**：每个 turn 的第一步注入一条占用读数（已用 / 窗口 / 百分比）。
   占比跨过档位线时各额外注入一次对应提醒，同一会话每档只提醒一次：
   - `handoverPercent`（默认 50）：该写交接了，长任务先把结论落盘；
   - `compactSoonPercent`（默认 75）：快到折叠线了，折叠只留摘要、细节会丢；
   - `nearlyFullPercent`（默认 90）：快满了，该换新会话了；
   - `ledgerPercent`（默认 50，**独立一档**）：顺带把这一场的结论落进长期记忆。

   前三档是提醒阶梯，另有一个「写长期记忆」独立档：它不挂在交接档上，水位可以跟交接不同
   （比如交接 50、落账 70）。四个档**都没有独立总闸**：哪个百分比填 **0** 就是关掉哪一档
   （`0/0/0/0` = 四档全关）。折叠 / 用完两档还各有一个「提醒」勾，不勾与填 0 等效；
   写长期记忆档没有勾。

   跨过 **handover** 这一档的那一次，若勾了「写交接（落模板文件）」，还会在 `clockFile` 同目录
   落一份**交接模板**文件（`交接-<yyyy-MM-dd>-<会话 id 后 8 位>.md`），并在注入里追加一行它的
   绝对路径。只写文件、不往上下文里塞模板正文；已存在就不覆盖、不追加；另几档不生成模板。
   交接档那个勾管的是**落不落模板**，不勾也照样发「该写交接了」那条提醒。
2. **时钟续行**：按固定间隔往一个文本文件追加 `YYYY-MM-DD HH:mm` 一行；能读到占用时行尾带上百分比。
   进程启动时先补一行，把上次关机期间的空白收口。
3. **换新提醒**：按周期三选一（按间隔 / 每周 / 每月）注入「该换会话」提醒，提醒过就记状态；
   到点那一拍还会另外往时钟文件写一行 `YYYY-MM-DD HH:mm · 该换会话`（能读到占用时带 ` 上下文 NN%`）。
   **换新动作不在插件里**——只提示，实际换会话走外置脚本 `tools/rotate-qq-session.mjs`
   （先写交接、再改绑定、最后重启）。

前两件只做**读数和提示**，不改任何行为、不代替折叠、不删历史；第三件只发提醒，不读写任何别人的存储。

三件事的注入都受顶层 `scopeSessions` 限定：留空 = 所有会话；填了会话 id（或前缀）就只在那些会话里注入。
**时钟行不受它影响**，按 `clockIntervalHours` 照常写。

## 为什么做这个

长会话会一直折叠、一直累计。折叠只压当前窗口，压不掉累计消耗；判断「这一场该不该换新」需要一个模型
自己看得见的读数。界面上有那个百分比，但模型读不到它——这个插件把它注入进去。

另外几种提醒分开，是因为它们要求你做的事不一样：50% 只是「先落盘」，75% 是「要折叠了，细节会丢」，
90% 是「这场该收了」，写长期记忆则是「顺手把结论记下来」。一句话糊在一起，等于没有提醒。

三档提醒的开关就是它们各自的百分比：填 0 = 关掉那一档（整档不注入、交接档也不落模板）；
折叠 / 用完两档另外各有一个「提醒」勾，不勾与填 0 等效。交接档的勾只管「落不落模板文件」。
「写长期记忆」从交接档里**拆出来成了独立一档**（见 `docs/DESIGN.md`），自己的水位、自己的开，
不跟交接绑定。关掉哪一档就只静默那一档，别的档位、读数、时钟行、换新提醒都不受影响。

## 依赖哪些能力

这张表说的是每个功能**靠 DSH 的哪条接缝**、那条接缝不在时会发生什么。本插件不 import 任何
`@deepseek-ai/*` 包（它是从工作区 junction 进 profile 的，裸 import 会静默失败），下表列的是宿主
提供的能力，不是 npm 包依赖。

| 功能 | 依赖 | 缺了会怎样 |
|---|---|---|
| 水位读数、四档提醒、交接模板 | `agent/pre-step` 事件 + `ctx.tokenMeter.contextPressure(session)`（由 `@deepseek-ai/dsh-token-meter` 提供） | 读不到水位就一条都不注入；四档提醒与模板都基于水位，所以也不会触发 |
| 时钟行 | 无（只用 node 的 fs）；按进程定时器写 | 不依赖任何插件 |
| 换新提醒 | 无（纯时间计算，时区用配置里的 `timeZone`） | 不依赖任何插件，但要该会话发起请求才会注入 |
| 设置页 | `settings.section` 槽位（`@deepseek-ai/dsh-client-ui-settings`）+ 宿主的 `webServer` 提供 `/api/aux` | 没有 webServer 时面板读不到也存不了，只能改 `cordis.patch.yml` 的出厂默认 |
| 提醒写长期记忆（`ledgerPercent` 这一档） | `@deepseek-ai/dsh-mnemon` 提供的长期记忆与 `mnemon_remember` | 没装 mnemon 时那句提醒照发，但落账无处可落；不用 mnemon 的人把 `ledgerPercent` 填 0 关掉这一档 |

**本插件唯一可选的插件依赖就是 mnemon（只为「提醒落账」这一句），其它功能都不依赖第三方插件。**
除它之外**不依赖** `@deepseek-ai/dsh-time-context` 等任何可选插件；也**不读写 qqbot 的任何存储**
（换会话本身由外置脚本 `tools/rotate-qq-session.mjs` 做）。

## 安装

在 DSH 里 **插件 → 添加插件 → 选本地目录**，指到本仓库目录；或者用
`dsh plugin --profile <name> add file:<绝对路径>`。

装完重启桌面端（从托盘退出，不是关窗口）才生效。

## 装在哪里找

⚠️ **配置页不在插件页，也不在左侧主侧边栏。**

装好重启后：点**设置** → 左侧导航里找**「砚砚工具包」**（排在「语音模式」附近）。那一页才是改配置的地方。

插件页只显示它的介绍和图标，一个字都改不了——这是最容易让人以为"没装上"的地方。

## 配置

行 id 是 `aux`。`cordis.patch.yml` 里的十六项是**出厂默认**；装好之后在
**设置 → 砚砚工具包** 里改，保存即生效，不用重启：

| 键 | 默认 | 说明 |
|---|---|---|
| `scopeSessions` | `[]` | 全局生效范围。空数组 = 所有会话都收到读数与提醒；非空时只有会话 id 等于某一项、或以某一项开头的会话才会收到**任何注入**（读数、四档提醒、换新提醒）。**只管注入，不管时钟**——时钟行照常写。非数组回落默认。 |
| `clockFile` | `G:\yanyan-workspace\report-cache\clock.md` | 时钟文件绝对路径，父目录不存在会自动建。 |
| `clockIntervalHours` | `6` | 两次追加之间的间隔（小时），合法范围 1–168。 |
| `injectPerTurn` | `true` | 每轮第一步是否注入读数。关掉只影响读数，四档与换新提醒照常。 |
| `handoverPercent` | `50` | 提醒交接线（%），钳制到 0–100。**填 0 = 关闭交接档**：不提醒、不落模板。 |
| `handoverTemplateEnabled` | `true` | 交接档的勾：跨「提醒交接」线时**是否落交接模板文件**，并决定提醒里要不要追加「模板已生成」。只在 `handoverPercent` 大于 0 时有意义；不勾时交接提醒照发，只是不落盘（面板上是「写交接（落模板文件）」）。2.4.0 里这个键叫 `templateEnabled`。 |
| `compactSoonPercent` | `75` | 即将折叠线（%），钳制到 0–100。**填 0 = 关闭这一档**。 |
| `compactSoonEnabled` | `true` | 折叠档的勾：**是否发这条提醒**。不勾与把 `compactSoonPercent` 填 0 等效（面板上是「提醒」）。 |
| `nearlyFullPercent` | `90` | 即将用完线（%），钳制到 0–100。**填 0 = 关闭这一档**。 |
| `nearlyFullEnabled` | `true` | 用完档的勾：**是否发这条提醒**。不勾与把 `nearlyFullPercent` 填 0 等效（面板上是「提醒」）。 |
| `ledgerPercent` | `50` | **独立一档**「写长期记忆」的水位（%），钳制到 0–100。到线只在注入里说一句「顺带把这一场的结论落进长期记忆」，不落任何文件。**填 0 = 关闭这一档**；没有勾，也不参与三档的递增。 |
| `rotateReminderMode` | `'weekly'` | 换新提醒周期：`interval` / `weekly` / `monthly`。非法值回落 `weekly`。 |
| `rotateReminderDays` | `7` | 仅 `interval` 模式用：隔几天提醒，钳制到 1–365。 |
| `rotateReminderWeekday` | `6` | 仅 `weekly` 模式用：0 = 周日 … 6 = 周六；越界或非法回落 6。 |
| `rotateReminderDayOfMonth` | `1` | 仅 `monthly` 模式用：每月几号，1–28（每月都有）；越界回落 1。 |
| `timeZone` | `Asia/Shanghai` | 时钟行、以及换新提醒算「周几 / 几号」用的 IANA 时区。 |

四个布尔（`injectPerTurn`、三档各自的勾 `handoverTemplateEnabled` / `compactSoonEnabled` /
`nearlyFullEnabled`）都只认真正的布尔值：写成字符串 `"false"` 或数字 `0` 不算关，
会回落到 `cordis.patch.yml` 里的出厂默认（都是 `true`）。

三个百分比（三档提醒）允许 **0**；0 的含义是「关闭这一档」，而不是「第 0 名」。
**递增只约束大于 0 的三档**（提醒交接 < 即将折叠 < 即将用完）：设置页保存前会先拦一道，
不递增就地报错、不发请求；后端 `normalizeSettings` 还会再修一道——先把每项钳制到 0–100，
再把**大于 0** 的档按从小到大重排、仍相等（比如 `50/50/90`）就从低到高各加 1 撑开
（`[50,50,90]` → `[50,51,90]`）。0 的档不参与排序，原样保留。
例：`50/0/90` 合法；`0/70/50` 会被修正成 `0/50/70`；`0/0/0` 合法（三档全关）。

**`ledgerPercent` 是独立档，不在那条阶梯里**：它只钳制到 0–100，可以比交接低、可以在交接与
折叠之间、也可以和三档里的某一档相等（例如交接 50、落账 50，或交接 40、落账 70 都合法）。
它跟交接档**不绑定**：交接关掉不会顺手关它，它关掉也不影响三档提醒。

面板上的提醒区自上而下就是这么四行（某档填 0 时它后面的勾置灰，并给一行「该档已关闭」）：

```
提醒交接（%）   [ 50 ] %   ☑ 写交接（落模板文件）
即将折叠（%）   [ 75 ] %   ☑ 提醒
即将用完（%）   [ 90 ] %   ☑ 提醒
写长期记忆（%） [ 50 ] %   （无勾选，填 0 = 关闭）
```

老版本留下的旧键**已经删掉**：更早的 `handoverEnabled`，以及 2.4.0 的 `templateEnabled`
（改名为 `handoverTemplateEnabled`）和 `ledgerReminderEnabled`（被 `ledgerPercent` 取代）。
设置文件里残留了也不会报错、不会生效，规整时直接丢掉；要关档请把对应百分比改成 0。
2.4.0 删过的 `compactSoonEnabled` / `nearlyFullEnabled` 在 2.5.0 加回来了。

设置页把值保存在 `%USERPROFILE%\.dsh\aux-settings.json`；「恢复默认」会删掉这个文件，回到 patch
里的值。也可以直接改那个 JSON —— 宿主每次 pre-step 与时钟 tick 前都会看文件 mtime，变了就重读。

## 交接模板

跨过 `handoverPercent` 那一次（也就是注入「该写交接了」的那条提醒时），若交接档的勾勾着
（`handoverTemplateEnabled`，默认勾），还会在 `clockFile` 同目录（默认 `G:\yanyan-workspace\report-cache\`）
**落一份模板文件**。只写文件，不碰别的进程的存储；写盘失败一律吞掉，不影响提醒与读数。

交接档怎么开：`handoverPercent` 大于 0 就发「该写交接了」那条提醒（填 0 = 整档关闭，
既不提醒也不落模板）。紧挨着它的那个勾管「落不落模板文件」：`handoverTemplateEnabled`
（面板上「写交接（落模板文件）」）取消勾选 → 提醒照发，只是不落文件、文案里也不出现
「模板已生成」（文件之前生成过也不提）。交接档填 0 时这个勾会置灰，并给一行「该档已关闭」。

「写长期记忆」**不在交接档里**：它是独立的 `ledgerPercent` 一档，只注入一句
「顺带把这一场的结论落进长期记忆。」，不碰模板、不落任何文件。交接档开不开、模板落不落，
都跟它无关；不想看见这句就把 `ledgerPercent` 填 0。

- **文件名**：`交接-<yyyy-MM-dd>-<会话 id 后 8 位>.md`，例 `交接-2026-11-18-ca1a4b99.md`。
  日期按机器**本地时区**取；会话 id 里的非字母数字字符（`-`、`:`、`/` 等）一律换成 `_`，
  保证是合法文件名；id 不足 8 位就全用，洗过之后没剩下字符则用 `unknown`。
- **标题**：`# 交接 · <日期>（会话 <会话 id 前 8 位>）`。DSH 的 id 常以 `session-` 开头，
  直接取前 8 位会全部变成 `session_`，所以拼标题时**先摘掉这个公共前缀再取前 8 位**
  （`session-3df4e987-ca1a-...` → `3df4e987`）；没有该前缀的 id 就是字面前 8 位。
- **只生成一次**：同一会话同一天只生成一次。文件已存在就**不覆盖、不追加**，直接跳过写盘，
  但注入里**仍然给出路径**（说明之前已经生成过）。
- **只在 handover 触发**：`compactSoonPercent` / `nearlyFullPercent` / `ledgerPercent` 只提醒、
  不落文件。`scopeSessions` 范围外的会话本来就不注入，也就不会生成。
- **注入里只放指针**：提醒文案后追加一行 `模板已生成：<绝对路径>`，模板正文只留在文件里，
  不占每轮上下文（理由见 `docs/DESIGN.md`）。
- **模板五段**（写死的骨架，不做成配置）：
  1. 本场做了什么（3–5 条，一句话一条）；
  2. 下一场必须知道的（路径、版本、坑、在哪找东西；写得让下一个我不用翻聊天记录）；
  3. 没做完的（带为什么没做，以及卡在哪）；
  4. 要落账的条目（每条形如「编号 / 原话或来源 / 决策 / 代价 / 反例 / 被压掉的细节」，
     写完标「已落账」，定期整理时一眼看得出哪些还没归并）；
  5. 这次有没有改热记忆（有则写改了什么、什么时候；没有就写「没有」）。

## 换新提醒

- **状态文件**：`%USERPROFILE%\.dsh\aux-state.json`，只放状态、不放设置，形如
  `{ "lastRotateReminderAt": "2026-11-18T12:00:00.000Z" }`。文件不存在 / 读坏 = 从没提醒过。
- **什么时候提醒**：**每次 pre-step 都检查**（不限第几步）；从未提醒过（第一次运行）→ 立刻提醒；
  之后按 `rotateReminderMode` 判到期：
  - `interval`：距上次提醒满 `rotateReminderDays` 天（1–365）；
  - `weekly`：上次提醒之后最近的、落在 `rotateReminderWeekday`（0=周日 … 6=周六）的自然日到了；
  - `monthly`：上次提醒之后最近的、`rotateReminderDayOfMonth`（1–28）那个自然日到了。

  「周几 / 几号」都按 `timeZone` 算本地日期，不是 UTC。到点只注入一条：
  「本周换会话提醒：这一场已经用了 X%（窗口 Y）。要换就说一声，我按 `tools/rotate-qq-session.mjs`
  走——先写交接，再改绑定，最后重启。」
- **补提醒**：关机期间错过的那次，下次打开的第一轮就会补上，而且只补一次（写完时间就不到期了）。
- **时钟文件里留一行**：到点注入的同一次，另外往 `clockFile` 追加一行
  `YYYY-MM-DD HH:mm · 该换会话`，能读到水位时再带 ` 上下文 NN%`（例：
  `2026-11-18 20:50 · 该换会话 上下文 66%`）。它跟按 `clockIntervalHours` 写的常规时钟行是两回事，
  互不覆盖、也不去重；写失败吞掉，不影响注入。
- **生效范围（全局）**：`scopeSessions` 非空时，只有会话 id 等于某一项、或以某一项开头的会话
  才会收到**任何注入**（读数、四档提醒、换新提醒）；空数组 = 所有会话。范围外的会话一条都不注入，
  也不推进读数门限、已提醒档位和换新提醒状态。跳过时会在时钟文件同目录的 `aux-debug.log`
  里写一行 `skip scope session=<id>`，方便排查「这个会话怎么没读数」。**时钟行不受影响**。
- **换新本身不在这里**：插件不读不写 qqbot 的 `model-prefs.json`，也不缓存任何绑定。实际换会话
  由外置脚本 `tools/rotate-qq-session.mjs` 做（先写交接，再改绑定，最后重启桌面端）。
- 读不到状态文件、写失败都不影响会话：读失败当作从没提醒过，写失败吞掉（本进程内另有内存计时兜底，
  不会每个 pre-step 重复提醒）。

## 已知限制

- **读不到水位就不注入**：`pressureTokens` 或 `contextWindow` 缺失、为 0 时静默跳过，不会伪造读数。
  这通常意味着宿主刚启动、还没发出过请求。
- **提醒只按会话内存记**：插件重启后，同一会话的四档提醒会重新计一次。交接模板也一样：
  重启后再跨线会再做一次写盘检查，但文件已存在就不会重写，注入里会再给一次路径。
- **关掉的档位不记账**：某一档的百分比为 0（或折叠 / 用完两档的勾没勾）时，跨过线也不注入、
  也不记「已提醒」，所以中途把它改回打开、水位仍在该档之上，会补发那一次提醒。
  模板同理：`handoverTemplateEnabled` 没勾就不生成文件，勾上后下一次跨线才生成。
- **生效范围只认会话 id 前缀**：`scopeSessions` 是字符串前缀匹配（等于或以其开头），写错前缀那个会话
  就一条注入都收不到；留空最稳（所有会话都收）。范围外的会话连读数都没有，这是刻意的。
- **时钟行只随进程活着写**：电脑关机或桌面端退出期间不会写；下次启动补一行，但中间那段的空白不会补。
- **换新标记行只在到点那一次写**：`· 该换会话` 那一行是提醒时的附加记录，常规时钟行不会带它；
  两者碰巧同一分钟都写也并排留着。
- **只注入文本**：不提供模型可调用的查询工具，读数只在每轮开头可见。
- **没有 webServer 的 profile 不挂接口**：`webServer` 服务不是必需项，探测不到就只跳过 `/api/aux`
  路由（设置页不可用），水位、提醒与时钟照常跑。
- 不接管 DSH 的自动折叠，也不改变压缩阈值——那是 `compaction-basic` 的事。

## 开发

改 `index.js` 后，ESM 语法检查用自带的解析器（`node --check` 对含 `export` 的文件会直接放行，别信它）：

```sh
node --experimental-vm-modules <check-esm-syntax.mjs 的路径> index.js
```

`client.js` 是自注册脚本而不是 ESM，用另一支检查：

```sh
node <check-client-script.cjs 的路径> client.js
```

纯逻辑都有普通 node 测试（不装依赖）：

```sh
node test/settings.test.mjs
node test/rotate-schedule.test.mjs
node test/handover.test.mjs
```
